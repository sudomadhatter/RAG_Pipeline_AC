# RKP Manifest Creation Skill

> **Owner:** Woz (Agent) — receives master modules from Daniel (CFI).
> **Trigger:** Daniel provides a master module `.md` file and requests RKP creation.
> **Output:** One or more `{lesson_id}_rkp.json` files in `curriculum_components/rkp_manifests/`.

---

## 1. What You Receive (Inputs)

Daniel delivers a **master module** markdown file. These live in:
`curriculum_components/curriculum_modules/`

Each master module covers **one ACS Task** (e.g., "Area I, Task A") and contains
multiple ACS elements. Each element has 4 sections:

```
## PA.I.A.K1: [Element Title]
> Context: ...

#### 1. The Oral Standard (The Direct Answer)
[2-4 sentence answer a student must articulate]

#### 2. The Expert Deep Dive (The "Textbook")
[Multi-paragraph teaching content with subsections]

#### 3. Common Errors & Gotchas
[Bullet list of traps and misconceptions]

#### 4. Bridge Keys (Metadata)
* Regs: [FAR citations]
* Docs: [PHAK chapters, ACs, handbooks]
* Keywords: [search terms]
```

---

## 2. What You Produce (Outputs)

For each master module, you create **multiple lesson-level RKP manifests**.
One master module → typically 2-5 RKP JSON files, depending on how many
ACS elements group into logical lessons.

### 2.1 The Lesson Split

Use the **ACS Element to Lesson ID Mapping** from `curriculum_components/quiz_schema.md`
(lines 118-155) as the definitive guide for which elements belong to which lesson.

If a new Area/Task has no existing mapping, propose one to Daniel for approval
before building the JSON files.

### 2.2 The Exact JSON Schema

Every RKP file MUST follow this structure exactly:

```json
{
  "lesson_id": "PPL_PA_{AREA}_{TASK}_{SEQ}",
  "title": "Human-Readable Module Title (3-6 words)",
  "acs_task_reference": "Area {N}, Task {L}",
  "acs_element_keys": ["PA.{AREA}.{TASK}.K1", "PA.{AREA}.{TASK}.K2"],
  "required_knowledge_points": [
    {
      "id": "RKP_01",
      "title": "Short headline (2-5 words)",
      "why": "One sentence: why this matters for a student pilot.",
      "knowledge": "The core teaching paragraph — plain text, factually complete.",
      "acs_elements": ["PA.{AREA}.{TASK}.K1"],
      "far_references": ["14 CFR 61.56"],
      "bridge_keys": ["FAA-H-8083-25C", "AC 61-98D"],
      "knowledge_formatted": ""
    }
  ],
  "lesson_overview": "## Title\n\n[500-1000 word narrative essay]",
  "audio_file": "PPL_PA_{AREA}_{TASK}_audio.m4a",
  "video_file": "PPL_PA_{AREA}_{TASK}_video.mp4"
}
```

## 3. Field-by-Field Rules

### `lesson_id`
- Pattern: `PPL_PA_{AREA}_{TASK}_{SEQ}`
- Area uses Roman numerals: `I`, `II`, `III`, `IV`, `V`, `VI`, `VII`, `VIII`, `IX`, `X`, `XI`
- Task is a single uppercase letter: `A`, `B`, `C`, `D`
- Sequence is zero-padded 2-digit: `01`, `02`, `03`

### `title`
- 3-6 words. Human-readable. Do NOT include the ACS code.

### `acs_task_reference`
- Format: `"Area {N}, Task {L}"` using Roman numerals.

### `acs_element_keys`
- ALL element codes this lesson covers. Must match the master module exactly.
- Format: `PA.{AREA}.{TASK}.{TYPE}{NUM}` where TYPE is K/R/S.

### `required_knowledge_points` (3-6 per lesson, target 4)

| Field | Source | Rules |
|---|---|---|
| `id` | Sequential | `RKP_01`, `RKP_02`, etc. Reset per lesson. |
| `title` | Derived from element heading | 2-5 words. Flashcard front headline. |
| `why` | Agent writes | One sentence. Practical importance. NOT "the DPE will ask." |
| `knowledge` | **From master module §1 "The Oral Standard"** | 2-4 sentences. Include FAR numbers. **NEVER modify after Daniel approves.** |
| `acs_elements` | From master module | Which element code(s) this RKP covers. |
| `far_references` | From master module §4 "Regs" | Format: `"14 CFR 61.56"`. |
| `bridge_keys` | From master module §4 "Docs" | **DOCUMENT-LEVEL ONLY.** See bridge_key_guide.md §3.3. |
| `knowledge_formatted` | **LEFT BLANK** — auto-generated by script | Set to `""`. |

### `lesson_overview`
- 500-1000 word narrative essay tying all RKPs together.
- Tone: Conversational expert CFI at the whiteboard.
- See `PPL_PA_I_A_01_rkp.json` as the gold standard.

### `audio_file` / `video_file`
- Auto-hydrated by `generate_knowledge_formatted.py` script.
- Pattern: `PPL_PA_{AREA}_{TASK}_audio.m4a` / `PPL_PA_{AREA}_{TASK}_video.mp4`

---

## 4. Coverage Rules (Non-Negotiable)

1. **Every ACS element** in the master module must be covered by at least one RKP.
2. **3-6 RKPs per lesson** (target 4).
3. **One RKP can span multiple elements** if closely related.
4. **No phantom RKPs** — each distinct knowledge area gets its own RKP.

---

## 5. Bridge Key Rules (Critical)

1. **`bridge_keys` MUST be document-level tokens** matching DB2's `document_tags` vocabulary:
   - ✅ `FAA-H-8083-25C`, `AC 61-98D`, `AIM`, `14 CFR 91`
   - ❌ `FAA-H-8083-25C (PHAK Ch 6)`, `AIM 8-1-5`
2. **`bridge_keys` may NEVER be empty.** At least 1 document key per RKP.
3. **`far_references` may be empty** for non-regulatory topics — but **never write "N/A"**.

## 6. Execution Pipeline

### Step 0: Read these references FIRST (before building any JSON)
- **`faa-grounding-gate` skill — MANDATORY.** Every fact you write into a `knowledge`, `why`,
  `far_references`, or `lesson_overview` field must trace to an ACS/FAA source document on disk.
  Never write a regulation, number, or requirement from memory. Unverifiable ⇒ flag for Daniel.
- **`_docs/instruction_docs/rkp_creation_guide.md`** — the schema, field rules, and the reverse-contract
  (every fact a quiz will test must live in a `knowledge` field, not only the `lesson_overview`).
- **`_docs/instruction_docs/bridge_key_guide.md`** — the bridge-key contract (document-level tokens, DB2
  vocabulary, how to verify). `bridge_keys` may never be empty.
- **The source master module** in `curriculum_components/curriculum_modules/` (read it in full).

### Step 1: Analyze the Master Module
- Read the entire master module. List all ACS element codes.
- Cross-reference against the ACS Element to Lesson ID mapping.

### Step 2: Present the Split to Daniel
- Show the proposed lesson split before building JSON. Wait for approval.

### Step 3: Build the RKP JSON Files
- Construct the full JSON per lesson.
- Extract `knowledge` from §1, `far_references` from §4 Regs, `bridge_keys` from §4 Docs.
- Leave `knowledge_formatted` as `""`.

> [!IMPORTANT]
> **Claude-specific tooling note:** The `write_to_file` tool may stall on JSON files
> in certain directories. If this happens, use PowerShell via `Bash`:
> ```bash
> cat > curriculum_components/rkp_manifests/PPL_PA_II_A_01_rkp.json << 'EOF'
> { ... your JSON ... }
> EOF
> ```

### Step 4: Run `generate_knowledge_formatted.py`
```bash
cd curriculum_components/scripts
python generate_knowledge_formatted.py --all --write
```

### Step 5: Validate
- Confirm every ACS element has at least one RKP.
- Confirm `bridge_keys` are non-empty and document-level.
- Run the bridge key verification skill.

### Step 6: Present to Daniel for Review

## 7. Naming Convention Reference

| Component | Pattern | Example |
|---|---|---|
| **Lesson ID** | `PPL_PA_{AREA}_{TASK}_{SEQ}` | `PPL_PA_II_A_01` |
| **RKP File** | `{lesson_id}_rkp.json` | `PPL_PA_II_A_01_rkp.json` |
| **Quiz File** | `{lesson_id}_quiz.json` | `PPL_PA_II_A_01_quiz.json` |
| **Audio** | `PPL_PA_{AREA}_{TASK}_audio.m4a` | `PPL_PA_II_A_audio.m4a` |
| **Video** | `PPL_PA_{AREA}_{TASK}_video.mp4` | `PPL_PA_II_A_video.mp4` |

---

## 9. Anti-Patterns

| ❌ Don't | ✅ Do Instead |
|---|---|
| Modify the `knowledge` field after Daniel approves | Treat it as immutable |
| Use chapter-level bridge keys | Use document-level tokens |
| Leave `bridge_keys` empty | Always ≥1 document key |
| Write `"N/A"` in any field | Use `[]` or omit |
| Create RKPs without master module source | Wait for Daniel |
| Write a reg/number/requirement from memory | Read the source PDF first (`faa-grounding-gate`) |
| Skip the lesson split approval step | Always show Daniel first |
| Generate `knowledge_formatted` manually | Use the script |
